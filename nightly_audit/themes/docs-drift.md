# テーマ: docs-drift (ドキュメント/コメントと実装の乖離)

> お手本テーマ。実績あり (environment 格上げ・yolo compose 移動でドキュメントのパスが
> コードに追従していなかった事例が複数あった)。低リスクで自動修正に向く。
> 2026-06-22 に初回試走で実戦調整済み (下記の除外/要相談ルールと実例)。

## 対象リポ
- project_rf_rover, project_drone2, acsl_infra  (存在するものだけ)

## 観点 (チェックリスト)
- [ ] README / CLAUDE.md / docs/ / AGENTS.md / スクリプト先頭コメントに出てくる
      **ファイルパス・ディレクトリ**が実在するか (移動/リネーム後の取り残し)
- [ ] ドキュメント記載の**コマンド/サブコマンド/フラグ**が実在するか
      (`dup <mode>`, `acsl ...`, `./setup <variant>`, `colcon ... --packages-select <pkg>`)
- [ ] config キー名・既定値の記述が実 yaml と一致するか
- [ ] コード内コメントが指す関数/ファイル/行の前提が現状と合うか
- [ ] 相対リンク (`[text](../path)`) のリンク切れ

## 走査方法 (allowlist 据え置きのため組込みツールで)
- 走査は **Grep / Glob / Read の組込みツール**で行う (shell の `git ls-files`/`python3` 等は
  dontAsk の allowlist 外で拒否されるため使わない)。
- 追跡対象の `.md` と主要スクリプトから `[text](path)` の相対リンク・バッククォート内の
  パス・コマンド記述を抽出し、Glob/Read で実在を確認する。

## 除外 (誤検知を出さない)
- **`nightly_audit/**` (この監査自身の文書) は対象外** — テーマ説明中の例示リンクを誤検知する。
- **インラインコード内の例示** (例: 「相対リンク `[text](../path)`」の `../path`) は
  実リンクではないので指摘しない。
- 自動生成物・サブモジュール配下は対象外。

## 「指摘」とみなす条件
- 参照先が**実際に存在しない**もの (Glob/Read で確認)。
- **かつ正しい参照先が一意に定まる** (どう直すか自明) もの。
  - OK 例 (試走で実検出): `acsl_interfaces/README.md` の `RcChannels.msg` は実体が `Rc.msg`
    (リネーム取り残し・説明文も一致) → 一意に直せる = 指摘。
- 参照先が消えていて**正しい修正先が一意でない**ものは指摘にせず**レポート「要相談」**へ:
  - NG 例 (試走): `docker/README_DOCKER.md` の `../systemd_files/setup.sh` 等
    (`systemd_files/` ごと消失。移動先が断定不可)。
  - NG 例 (試走): `packages/README_ROS.md` が参照する複数パッケージ README
    (このリポに dir が無い。外部配置/廃止の判別不可。一括削除は危険)。

## 自動修正してよい範囲
- パス/コマンド/キー名の**追従修正** (実装側は変えず、ドキュメント/コメントを実態に合わせる)。
  リンクの**表示名**も実体に合わせる (例: `[RcChannels.msg]` → `[Rc.msg]`)。
- 明白な typo・リンク切れ修正。
- 不可 (要相談): 実装の方を変える / 仕様を解釈して書き換える / 行をまとめて削除する。

## 検証方法
- 修正後、その参照先を Glob/Read で実在確認。
- スクリプトコメントを直した場合も `bash -n` / `py_compile` で本体無傷を確認。
