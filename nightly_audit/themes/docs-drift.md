# テーマ: docs-drift (ドキュメント/コメントと実装の乖離)

> お手本テーマ。実績あり (environment 格上げ・yolo compose 移動でドキュメントのパスが
> コードに追従していなかった事例が複数あった)。低リスクで自動修正に向く。

## 対象リポ
- project_rf_rover, project_drone2, acsl_infra  (存在するものだけ)

## 観点 (チェックリスト)
- [ ] README / CLAUDE.md / docs/ / AGENTS.md / スクリプト先頭コメントに出てくる
      **ファイルパス・ディレクトリ**が実在するか (移動/リネーム後の取り残し)
- [ ] ドキュメント記載の**コマンド/サブコマンド/フラグ**が実在するか
      (`dup <mode>`, `acsl ...`, `./setup <variant>`, `colcon ... --packages-select <pkg>`)
- [ ] config キー名・既定値の記述が実 yaml と一致するか
- [ ] コード内コメントが指す関数/ファイル/行の前提が現状と合うか
- [ ] 相対リンク (`[..](../foo)`) のリンク切れ

## 「指摘」とみなす条件
- 参照先が**実際に存在しない** (grep / ls で確認) もの。
- かつ**正しい参照先が一意に定まる** (どう直すべきか自明) もの。
- 「説明が古いが直し方に解釈の余地がある」ものは指摘にせずレポートの「要相談」へ。

## 自動修正してよい範囲
- パス/コマンド/キー名の**追従修正** (実装側は変えず、ドキュメント/コメントを実態に合わせる)。
- 明白な typo・リンク切れ修正。
- ❌ 実装の方を変える / 仕様を解釈して書き換える のは不可 (要相談)。

## 検証方法
- 修正後、その参照先を `ls` / `grep` で実在確認。
- リンクは対象ファイルの存在確認。
- スクリプトコメントを直した場合も `bash -n` / `py_compile` で本体無傷を確認。
